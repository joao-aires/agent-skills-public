# Skills across the SDLC

I use the [common seven-phase breakdown](https://www.ibm.com/think/topics/sdlc): **planning, requirements analysis, design, implementation, testing, deployment and maintenance**. Other models group the phases differently. Discovery identifies what is worth building; feedback checks whether the delivered product helped and informs the next cycle. Both can happen during development. The boundaries in the diagram describe scope, without requiring sequential handoffs.

![Project foundations, discovery, seven-phase SDLC cycle, product feedback and skills across the lifecycle](images/sdlc-cycle.svg)

Choose the skills that help with the current task. Research, clarification and writing support every phase. Project foundations sit outside the repeating cycle and change as the application evolves.

Project foundations sit outside the repeating cycle: establish structure, stack constraints, instructions, local setup and delivery capabilities for a new project, then maintain the affected parts as it evolves. The entry arrow into Planning is not a required setup gate for every change. CI/CD is a maintained capability used during implementation, testing and deployment.

Across discovery, development and feedback: [humanizer](https://github.com/blader/humanizer/blob/225a6f39ac85f76ee48dbad772ea4abe4ed6c9d8/SKILL.md) edits prose in every phase, preserving meaning, commands and factual caveats. [research](https://github.com/mattpocock/skills/tree/4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d/skills/engineering/research) and [grill-me](https://github.com/mattpocock/skills/tree/4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d/skills/productivity/grill-me) can support any relevant phase. `grill-me` still starts only on an explicit request; placing it here does not authorize automatic interrogation. [maintain-documentation](../plugins/development-workflow/skills/maintain-documentation/SKILL.md) keeps project knowledge aligned; [contribute-code](../plugins/development-workflow/skills/contribute-code/SKILL.md) supplies the default worktree/commit/PR flow; [design-secure-features](../plugins/development-workflow/skills/design-secure-features/SKILL.md) revisits data and authority risks. Trail of Bits skills support specific security and dependency reviews; they do not cover every security or privacy concern. Capacity, cost and recovery constraints inform design as well as maintenance. CI/CD supports implementation and testing as well as deployment.

The wider catalogue includes helpers and stack tools for more specific tasks. See the [upstream catalogue](maintainer-reference.md#upstream-catalogue) and [workflow selection](../plugins/development-workflow/WORKFLOW.md) for the wider inventory. Tickets remain optional.

## Reliability across phases

`reliability-design` follows the user outcome from requirements into design, acceptance and operation. `observability-operations` implements and checks the signal contract as code and topology evolve. Neither is confined to maintenance. Runbooks support deployment and response; incident learning feeds the next requirements/design iteration, separate from product feedback about value.

The cycle image shows representative entry points; the table and [usage guide](usage.md) carry the wider inventory. Kubernetes resource guidance applies only to Kubernetes; JVM tuning applies only to JVM workloads. Datadog/Terraform monitoring is an optional implementation example.

## Performance and remaining failure-testing coverage

[test-application-performance](../plugins/development-workflow/skills/test-application-performance/SKILL.md) provides k6 guidance for local development, an application started on a CI runner, and a deployed non-production target. It connects design/capacity assumptions to testing and deployment verification. Thresholds, achieved load, semantic outcomes and evidence boundaries are explicit; runner results do not establish production capacity.

Detailed fault-injection and chaos-engineering operating instructions remain to be added. Existing capacity/JVM guidance and post-load recovery checks provide narrower evidence.
