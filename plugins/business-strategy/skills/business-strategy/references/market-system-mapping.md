# Market System Mapping

## Purpose

A market is a system of users, buyers, suppliers, platforms, channels, complements, substitutes, incentives, and evolving technology. A competitor list alone misses where value is created and captured.

## Map the system

### Actors

Identify:

- end users
- economic buyers
- beneficiaries
- approvers / blockers
- suppliers
- distributors / channels
- platforms
- partners / complements
- regulators / standards bodies
- service providers
- internal teams that can substitute for a vendor

Do not assume the user and buyer are the same person.

### Workflow / value chain

Map how the job is performed today:

```text
trigger → discovery → evaluation → purchase → setup → core workflow → handoff → measurement → renewal/expansion
```

For infrastructure or platform products, map the technical value chain as well.

### Money and profit pools

Ask:

- Where does budget exist today?
- Which existing spend can be replaced?
- Which new budget must be created?
- Who captures the highest margins?
- Which participant controls procurement or distribution?
- Where are costs or risks externalized onto another actor?

A large amount of activity does not automatically imply an attractive profit pool.

### Alternatives

Include:

- direct products
- adjacent products
- manual work
- spreadsheets / generic tools
- consulting / services
- internal build
- doing nothing

The status quo is often the strongest competitor.

## Layer map

For technology markets, separate layers such as:

```text
user experience / application
workflow / orchestration
control / governance
platform services
runtime / infrastructure
models / core technology
hardware / underlying resources
```

Use domain-specific layers rather than forcing this exact stack.

For each layer identify:

- differentiated players
- commoditizing capabilities
- standards
- switching costs
- ecosystem leverage
- likely bundling
- where the company proposes to sit

## Bottlenecks and control points

Ask:

- What scarce resource or coordination problem limits the system?
- Which layer must many participants pass through?
- Who owns identity, data, distribution, transaction flow, workflow state, or trust?
- If a bottleneck disappears, where does value migrate?

The most visible product layer is not always the best strategic layer.

## Market lifecycle and evolution

Characterize the market as emerging, growing, consolidating, mature, or declining only when the label improves the decision.

Then identify:

- what is becoming standardized
- what is becoming cheaper
- what is becoming easier to build internally
- what new complexity appears as the old complexity disappears
- which complements become more valuable as core technology commoditizes

## Profit-pool migration

When an underlying capability commoditizes, value may move to:

- distribution
- integration
- workflow ownership
- governance / assurance
- proprietary data
- ecosystem
- services around operational complexity

Do not equate technical differentiation with durable value capture.

## Deliverable

A useful market-system synthesis includes:

1. actors and incentives
2. workflow / value chain
3. money and budget flow
4. layers and ownership
5. alternatives and substitutes
6. bottlenecks / control points
7. current profit pools
8. expected migration of value
9. strategic implications

End with implications for **where to play**, not merely a market diagram.
