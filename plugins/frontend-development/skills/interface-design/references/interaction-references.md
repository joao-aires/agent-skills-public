# Interaction references

- [NN/g wireflows](https://www.nngroup.com/articles/wireflows/) illustrates combining screen structure with transitions; use it when a static page sketch would omit important interaction behavior.
- [NN/g consistency and standards](https://www.nngroup.com/articles/consistency-and-standards/) distinguishes coherent internal patterns from platform expectations. Preserve legitimate product and accessibility differences.
- [GOV.UK patterns](https://design-system.service.gov.uk/patterns/) provides examples of task-oriented interaction guidance. Borrow reasoning for relevant patterns, not government branding or a new component library.
- [WCAG quick reference](https://www.w3.org/WAI/WCAG22/quickref/) supports specific accessibility questions. Keyboard, focus, status and error behavior require actual verification; accessible primitives alone do not establish conformance.

A compact example for broad dialog changes: record the entry points and roles, choose one shared modal/sheet pattern for short edits, specify submission/validation/cancel/focus behavior, implement a representative caller, then verify all callers and contextual exceptions. Keep coverage status in the existing work record. No screenshot or diagram establishes API authorization or persisted results.
